# Roadmap

AegisForge grows by measured capability, not by accumulating prompts. Every stage must preserve the portable skill contract and add evaluation evidence before claiming improvement.

## Current foundation — 0.3.0

The current foundation provides deterministic risk assessment, explicit governance states, structured evidence ledgers, a searchable skill registry, explainable routing, schema checks, repository diagnostics, a reproducible scenario suite, portable adapters, and contributor-facing documentation. The large catalog remains honest about its maturity: most entries are experimental scaffolds.

## Next — safety and interoperability

The next release should add a formal approval-event schema, secret-redaction checks, dependency and action pinning checks, adapter manifests for major coding-agent harnesses, clean-session acceptance tests, and a generated searchable catalog view.

## Following — outcome evaluation

The evaluation system should grow to include locked benchmark versions, baseline comparisons, cost and latency reporting, reviewer calibration, adversarial cases, and published regression thresholds. Negative results and known failure modes should be reported rather than hidden.

## Production readiness

A production release requires deployment and observability adapters, migration verification helpers, progressive rollout and rollback templates, incident workflows, accessibility and performance automation, and domain packs with qualified review requirements.

## Ecosystem scale

Longer-term work includes signed releases, compatibility badges, community governance, translations, a deprecation policy, and contribution tooling that rewards measurable outcomes rather than repository size.

## Non-goals

AegisForge will not replace engineering judgment, guarantee security, autonomously approve high-impact changes, or optimize for repository size. The project will remain explicit about uncertainty and human accountability.
