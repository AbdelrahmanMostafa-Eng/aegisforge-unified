# Roadmap

AegisForge should grow by measured capability, not by accumulating prompts. Each stage must preserve the portable skill contract and add evaluation evidence before claiming improvement.

## Foundation: current release

The foundation provides adaptive risk assessment, portable bootstrap guidance, evidence and approval concepts, a skill catalog, core skill families, deterministic validation, a reference CLI, repository tests, and CI.

## Next release: safety and interoperability

Add a formal approval-event schema, secret-redaction checks, dependency and action pinning checks, adapter manifests for major coding-agent harnesses, clean-session acceptance tests, and a generated catalog website or searchable index.

## Following release: outcome evaluation

Add a versioned scenario suite with locked evaluation tasks, baseline comparisons, cost and latency reporting, reviewer calibration, adversarial cases, and regression thresholds. Publish negative results and known failure modes.

## Production release: lifecycle coverage

Add deployment and observability adapters, migration verification helpers, progressive rollout and rollback templates, incident workflows, accessibility and performance automation, and domain packs with qualified review requirements.

## Ecosystem release: community scale

Add contribution tooling, skill linting, signed releases, compatibility badges, a discoverability registry, maintainer governance, translations, and a deprecation policy. Reward skills that demonstrate measurable outcomes rather than only popularity.

## Non-goals

AegisForge will not claim to replace engineering judgment, guarantee security, autonomously approve high-impact changes, or optimize for repository size. It will remain explicit about uncertainty and human accountability.
